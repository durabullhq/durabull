Use this checklist to verify a new Durabull deployment. Each item links to the guide that explains
how to complete it.

## Before connecting production Redis

- Choose an [installation path](/documentation/self-hosting/installation).
- Confirm [authentication and persistence modes](/documentation/getting-started/architecture-and-modes).
- Replace example secrets and configure [environment variables](/documentation/getting-started/environment-variables).
- Set the [BullMQ prefix, Redis URL, and connection environment](/documentation/getting-started/connection-management).
- Apply [security and network controls](/documentation/operations/security-and-hardening).
- Preserve the database, encryption keys, and Redis data needed for recovery.

## Verify the dashboard

- Confirm your [queues and job counts](/documentation/workflows/queues-dashboard).
- Inspect [job details, logs, and stack traces](/documentation/workflows/job-lifecycle-and-debugging).
- Check [schedulers](/documentation/workflows/scheduled-jobs) and [worker connectivity](/documentation/workflows/workers-topology).
- Enable [BullMQ throughput metrics](/documentation/workflows/bullmq-native-metrics) in all workers.
- Review [Redis health history and thresholds](/documentation/workflows/redis-health-alerts).

## Prepare for routine operation

- Configure [team access](/documentation/workflows/team-and-invitations) when using authenticated mode.
- Test [Linear](/documentation/integrations/linear) or [webhook notifications](/documentation/integrations/webhooks) if you use alert routing.
- Bookmark [Troubleshooting](/documentation/operations/troubleshooting) and the [HTTP API Reference](/documentation/reference/http-api).
- Use a disposable queue to practice [queue operations](/documentation/workflows/queue-operations).
- If using assistants, verify [MCP access and approved scopes](/documentation/integrations/mcp-server).
