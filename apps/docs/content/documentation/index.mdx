Durabull helps you monitor BullMQ queues, inspect failed jobs, manage scheduled jobs, and
understand worker activity. It runs in a browser or desktop app and connects to the Redis
instances your BullMQ applications already use.

## Choose your starting point

| I want to… | Start here |
| --- | --- |
| Use the hosted app | [Open Durabull Cloud](https://app.durabull.io), then follow [How to Use Durabull](/documentation/getting-started/how-to-use-durabull) |
| Run the desktop app | [Desktop Apps](/documentation/getting-started/desktop-apps) |
| Host Durabull myself | [Self Hosting Setup](/documentation/self-hosting/setup), then [Installation](/documentation/self-hosting/installation) |
| Work on the source code | [Local Development](/documentation/getting-started/local-development) |
| Connect an AI assistant | [MCP Server](/documentation/integrations/mcp-server) |

You only need one installation path. After installation, configure a
[Redis connection](/documentation/getting-started/connection-management) and open the queues dashboard.
An empty Redis instance shows no queues until a BullMQ application creates them.

## Configure and operate a deployment

Use [Architecture and Modes](/documentation/getting-started/architecture-and-modes) to understand
authentication, connection management, and persistence. The
[Environment Variables](/documentation/getting-started/environment-variables) reference covers their settings.

For deployment, see [Docker Image and Compose](/documentation/deployment/docker) and
[Cloud vs Self-Hosted](/documentation/deployment/cloud-vs-self-hosted). Before exposing a deployment,
review [Security and Hardening](/documentation/operations/security-and-hardening).

When something fails, start with [Connection Troubleshooting](/documentation/getting-started/connection-troubleshooting)
or the broader [Troubleshooting](/documentation/operations/troubleshooting) guide. For automation,
use the [HTTP API Reference](/documentation/reference/http-api).

## During an incident

1. Confirm the selected environment and Redis connection.
2. Check queue counts and worker availability.
3. Inspect the affected jobs, logs, and stack traces.
4. Fix the underlying cause before retrying jobs.
5. Review the scope and consequences before deleting jobs or queue data.
