## Connection Sources

Durabull can source connections from two places.

### Env-Driven Connections (`DURABULL_ENV_CONNECTIONS=true`)

Connections are defined through environment variables:

```bash
DURABULL_REDIS_URL_MAIN=redis://localhost:6379
DURABULL_ENV_CONNECTIONS=true
DURABULL_REDIS_URL_MAIN_ENVIRONMENT=development
DURABULL_REDIS_URL_MAIN_PREFIX=bull
DURABULL_REDIS_URL_MAIN_ALLOW_SELF_SIGNED_CERTS=false
DURABULL_REDIS_URL_WORKERS=redis://localhost:6380
DURABULL_REDIS_URL_WORKERS_ENVIRONMENT=staging
DURABULL_REDIS_URL_DEFAULT=MAIN
```

Behavior:

- Connections are synchronized into org scope.
- Connection create/edit/delete endpoints return `403`.
- Restart the API after changing environment variables; connection definitions are cached per process.
- Connection names use uppercase letters, digits, and underscores, beginning with a letter (for example `MAIN` or `PROD_EAST`).
- `_PREFIX` defaults to `bull`; it must match the `prefix` option used by your BullMQ queues and workers.

### DB-Managed Connections (`DURABULL_ENV_CONNECTIONS=false`)

Connections are managed in UI/API:

- Create connection
- Test connection
- Edit name, URL, environment, default selection, BullMQ prefix, and TLS options
- Delete with guardrails

## Connection Validation and Safety

When creating/testing a connection URL:

- URLs must use `redis://` or `rediss://`. Private and internal hosts are allowed so Durabull can reach your infrastructure; URL validation is not a network isolation boundary.
- Connection test endpoint is rate-limited.
- Production error messages are sanitized.
- Redis connection URLs are encrypted at rest in the `redis_connection` table, including environment-managed connections. Set `DURABULL_REDIS_URL_ENCRYPTION_KEY` in either connection mode.

## Default Connection Rules

- The selected default is used as the organization-level routing fallback.
- In environment mode, `DURABULL_REDIS_URL_DEFAULT` selects the connection key. If it is unset or invalid, the first valid key in alphabetical order becomes the default.
- In database-managed mode, deleting a default connection promotes another remaining connection.
- The API permits deleting the last connection. Add another connection to resume queue operations. Deleting a connection removes its Durabull configuration, not its Redis database.

## UI Behavior

Connections are grouped and shown by environment:

- Development
- Staging
- Production

From connection selector:

- Switching connection updates route context to `/$orgSlug/c/$connectionId`.
